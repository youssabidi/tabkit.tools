Understanding Crontab Syntax & Expressions

What is a cron expression? A cron expression is a string of five space-separated fields used in Unix, Linux, Kubernetes, and cloud schedulers to define automated task execution intervals. The five standard fields correspond to: Minute (0-59), Hour (0-23), Day of Month (1-31), Month (1-12), and Day of Week (0-6, where 0 represents Sunday).

Automating recurring background tasks, database backups, cache invalidations, and batch scripts is a cornerstone of modern system administration and cloud engineering. The standard Unix crontab daemon interprets five positional arguments to determine the exact minute a scheduled job triggers.

While cron expressions are compact and versatile, complex schedules combining step values (e.g. */15), comma-separated lists, and weekday ranges can lead to unintended execution frequencies. Standard Five-Field Syntax

  • Field 1 (Minute): 0-59 (supports *, */n, n-m, n,m)
  • Field 2 (Hour): 0-23 (24-hour UTC or local time)
  • Field 3 (Day of Month): 1-31 (calendar day)
  • Field 4 (Month): 1-12 (January through December)
  • Field 5 (Day of Week): 0-6 (0=Sun, 1=Mon, 6=Sat)

Popular Crontab Recipes

  • */15 * * * * — Runs every 15 minutes
  • 0 0 * * * — Runs every midnight (daily rollup)
  • 0 9 * * 1-5 — Runs Mon-Fri at 9:00 AM (workday trigger)
  • 0 0 1 * * — Runs on the 1st of every month at 00:00

Standard Vixie Cron Rules & Timezone Traps

Classic 5-field cron omits seconds and evaluates schedules against the host or runner system clock unless a specific TZ variable is declared.

  • Day-of-Month + Day-of-Week OR Rule: In standard Vixie cron, when BOTH Day-of-Month and Day-of-Week are non-wildcard values, the job runs when EITHER matches—not only when both match.
  • GitHub Actions vs. Localhost TZ: GitHub Actions and Kubernetes CronJobs run schedules in UTC by default; convert local business hours carefully around Daylight Saving Time shifts.
  • Zero vs. Seven for Sunday: Most implementations treat both 0 and 7 as Sunday, while 1–5 covers Monday through Friday.

Frequently Asked Questions

What does */5 mean in crontab syntax?

The slash operator indicates a step value. When used in the minute field as */5, it evaluates to every 5th minute throughout the hour (0, 5, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55).

Does crontab support seconds by default?

Standard Unix and Linux crontab uses 5 fields (minute, hour, day of month, month, day of week) and does not evaluate seconds. Schedulers like Quartz or Spring Framework support an optional 6th field for seconds, but classic system crontab intervals resolve to one minute minimum.

How do timezones affect cron jobs in Docker and Kubernetes?

Most container base images default system time to UTC. If you configure a cron job for 0 9 * * * expecting 9:00 AM local time, it will trigger at 9:00 AM UTC unless you explicitly pass the TZ environment variable or set the timeZone property in Kubernetes CronJob specs.
