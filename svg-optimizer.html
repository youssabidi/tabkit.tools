Figma/Illustrator SVG Bloat & React Attribute Differences

Vector editors leave hidden Inkscape/Adobe XML namespaces, redundant decimal precision, and empty wrappers inside exported icons.

  • JSX CamelCase Attributes: React rejects hyphenated SVG attributes like stroke-width, fill-rule, and class; JSX conversion automatically maps them to strokeWidth, fillRule, and className.
  • Inline CSS Data URI Rules: Encoding # as %23 allows tiny vector icons and noise textures to embed cleanly directly inside CSS background-image url(...) rules without Base64 overhead.
  • Keep viewBox Intact: Always preserve the viewBox="0 0 W H" attribute so responsive CSS width/height classes scale vectors cleanly without clipping artwork.
  • Strip Invisible Metadata: Exporting from Illustrator or Inkscape leaves hidden editor metadata, guides, and empty groups; stripping them cuts SVG weight by 30% to 60% without affecting visual rendering.

Common Pitfalls & Engineering Troubleshooting

Over-Aggressive Decimal Precision Truncation

Reducing path coordinate precision from 3 decimal places down to 1 rounds curve control points aggressively, causing subtle geometric vectors and smooth curves to develop visible polygon jaggedness. Always visually inspect optimized vectors at high zoom levels.

Stripping Critical viewBox Attributes

Naive vector minifiers often strip the viewBox attribute in favor of fixed width and height dimensions. Removing viewBox destroys the SVG's ability to scale responsively with CSS (e.g. width: 100%), causing vector assets to clip or overflow on responsive viewports.

ID Attribute Collisions in Inline Web Documents

When multiple inline SVGs contain elements with identical ID attributes (such as id="a" or id="linear-gradient-1"), the first gradient definition in the DOM overrides all subsequent icons, causing icons to display incorrect colors. TabKit namespaces or flattens IDs.
